Bygone — chrome mockup

Implements the spec in chrome-design.md against the decisions in state-model.md. Same palette, same diff-gutter connector concept, same three scopes. The chrome moves from a 4-row header to: a single top bar, a thin pane header row carrying per-pane state, and a persistent status bar with position and keyboard hints.

  • Green = one-sided change; blue = paired change. Unchanged.
  • Focused pane gets a 2px blue edge + header tint + exclusive caret.
  • Ref labels carry kind chips (branch, commit, working tree, staged) so HEAD~1 and working tree stop looking identical.
  • Two Copy controls in the center column: each has an arrow on the edge toward the gutter (← / →). Only the direction with a writable target stays enabled; history shows both disabled.
  • View flags (collapse unchanged, ignore whitespace, follow renames, etc.) live in the overflow ⋯ menu.

1. Two-way file diff

Top bar: left = scope + breadcrumb, center = two Copy buttons (arrows on the inner edge point at the gutter — left button copies L→R, right button R→L; wrong direction disabled), right = change nav + overflow.

Keybindings at a glance

All three scopes share the same chrome shape and navigation model. Tab toggles focused pane everywhere. [ / ] is sibling-on-disk in file mode and older/newer in history mode — safe because the scopes don't overlap. Each copy button’s arrow points at the gutter (L→R vs R→L); the matching ⌘ shortcut applies when that target is writable.
